<h2>一、先把网段和用途对上</h2>

<h2>二、桥接还是 NAT</h2>
<p>桥接是把公网地址直接配在服务器网卡上，服务器自己就是公网节点。路径最短，排查最简单。</p>
<p>NAT 是服务器只拿内网地址，由路由器做地址转换。省地址，配置集中，但服务器看不到真实来源地址。</p>
<p>判断标准是业务要不要真实源地址。做访问控制、看日志要真实来源的，用桥接；只提供服务的，用 NAT 更省。</p>
<h3>桥接要注意广播域</h3>
<p>公网段直接接到交换机，等于把这段地址放进一个广播域，任何一台机器抓包都能看到别人的流量，隔离要靠 VLAN。</p>
<h2>三、服务器侧怎么绑地址</h2>
<p>Linux 上加地址用 ip addr add，写进配置文件才持久；Windows 在网络适配器里加附加地址，注意网关只配一个。</p>
<p>一块网卡绑多个地址时，只有主地址用来出站，除非显式指定源地址。多地址机器最容易出的问题就是出口地址不对。</p>
<p>如果要指定某服务从某个地址出去，用策略路由或绑定源地址。配置完必须验证，别假设默认行为符合预期。</p>
<h2>四、端口和服务怎么对应</h2>
<p>每台服务器内部端口可以一样，对外端口必须唯一。用不同高位端口区分，比给每台机器改监听端口更省事。</p>
<p>改外部端口时留意应用里写死的回调地址。登录回调、支付通知这类 URL 里带端口，改了端口不同步改配置就会失败。</p>
<p>映射规则和防火墙规则要一起改。只改映射不改防火墙，表现为连接超时，看起来像对方的问题，实际是本机拦了。</p>
<h2>五、出口地址要保持一致</h2>
<p>多地址机器如果不指定源地址，出站可能走默认路由对应的地址，导致去和回不是同一个地址，对端会话容易断。</p>
<p>对外提供服务的机器，入站和出站尽量用同一个地址。需要主动外联的业务，明确绑定出口地址，日志里也好追溯。</p>
<p>用地址查询站点从每台服务器各测一次，确认回显的地址和分配表一致。这一步五分钟，能省掉后面几小时的排查。</p>
<h3>多线路时更要注意</h3>
<p>双线接入时，回程路由不一定会原路返回。配置策略路由让入站和出站走同一条线路，能避免大量非对称路由问题。</p>
<h2>六、扩容时怎么加</h2>
<p>地址有富余时，新服务器直接按表拿下一个地址，配置方式照抄现有机器，改地址和端口即可。</p>
<p>地址用完时，优先把内部服务挪到内网，腾出公网地址；再考虑用反向代理把多个服务收进一个入口。</p>
<p>真要扩网段，提前和运营商确认前缀、路由通告时间、是否需要改网关。这几项确认完再动手，避免中途断服。</p>

<h2>常见问答</h2>
<h3>多台服务器能共用一个公网地址吗？</h3>
<p>答：可以，靠不同端口或反向代理区分。但需要独立地址做认证或白名单的场景不适合共用，隔离性会打折扣。</p>
<h3>桥接和 NAT 哪个更快？</h3>
<p>答：差别很小，都在毫秒级以下。桥接少一层转换，路径更短；NAT 多一次查表，实际业务感知不到。</p>
<h3>服务器绑了多个地址，出站用哪个？</h3>
<p>答：默认用主地址。要指定出口需要绑源地址或配策略路由，不指定时行为依赖系统默认路由，务必实测确认。</p>
<h3>加地址要不要重启网络？</h3>
<p>答：Linux 上动态添加通常不用重启，但要写入配置文件才能在重启后保留。生产环境建议在维护窗口操作，避免瞬断。</p>
